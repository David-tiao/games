# 混沌光轨实验室 | Neon Ball YOLO + Kalman

可以**完全在自己的 Linux 电脑上运行**的动态目标检测与预测实验。

**当前版本 V4.1：新增 `mot_core.py` 的多 ID 卡尔曼 + 匈牙利跟踪，切换「连接本机算法」后会显示多个小球的算法 ID 框与长尾。默认浏览器演示仍是单目标。旧的 100 分仍是 #1 球单目标评分，并非 MOT 总评分。**

工程有两条独立路径：

- **推荐路径：网页画布 → 本地 Python 服务 → 检测/估计/预测 → 网页叠加可视化**。无需 Linux 屏幕录制权限，在 Wayland / X11 都可以使用。上传的是网页 Canvas **像素 JPEG**，不读取小球 JS 坐标，也不发送到外部互联网。
- **研究路径：屏幕/视频 → Python OpenCV 窗口 → 检测/估计/预测/CSV**。使用 MSS 抓屏，在 X11 桌面最容易使用；Wayland 可能限制抓屏。

## V3.3 既有功能（V4.1 保留）

- **默认可运行的算法演示**：浏览器直接把小球主画布缩放读取像素，采用亮白核心连通域检测，接入 **α-β（alpha-beta）状态估计** 并外推 350ms。检测代码不查询小球的真实 `x/y`；真实位置仅由独立评估模块用于计算误差。**这不是 YOLO 神经网络**，在面板和按钮上都明确标注。
- **对比度更高**：检测框与算法尾迹使用与球体色相相差约 180 度的颜色，并有深色描边；估计位置用白色方框，未来预测使用菱形，和球体长尾样式完全区分。
- **专属算法长尾**：独立于柔光小球尾迹，采用清晰的虚线、黑色底边与小方块采样点。默认 **28 秒**，误差侧边栏内可调 **8~45 秒**；折叠面板不会停止检测。
- **可折叠误差分析**：页面默认收起右侧误差面板，右上角「展开误差分析」可展开；其中指标、时间曲线与变向事件三个部分还可独立折叠。
- **切换真实本地模型**：点击「连接本机算法」可切到 Python 服务：YOLO（已有权重时）或 OpenCV 视觉检测 + 卡尔曼。默认的浏览器演示只用于快速观察，不替代 YOLO 模型训练或精度评估。

## 1. Ubuntu 安装和一键启动（推荐）

解压后进入项目目录，然后：

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip
cd neon_ball_lab
./install.sh
./start.sh
```

浏览器会打开 **`http://127.0.0.1:8765/?v=4.1`**（由 Python 本地服务提供网页，避免旧 `file://` 页面缓存），网页默认**自动启动独立的像素演示检测 + αβ 状态估计**，无需 YOLO 权重或 Python 服务便能演示（直接双击 `index.html` 也可）。点击**「连接本机算法」**（或按 **T**）后切换到 Python OpenCV/YOLO + 卡尔曼滤波。检测框和算法长尾采用相对小球的反色色相，估计点为白色方框，未来 350ms 预测为橙色/紫色菱形。`./start.sh` 默认使用 `hybrid`：训练好 YOLO 权重时优先用 YOLO，未训练时自动用 OpenCV 经典检测算法。

按 **F** 全屏、**H** 隐藏所有界面、**E** 展开/收起误差分析、**D** 开关演示追踪、**M** 切换运动模式、**Space** 暂停、**T** 切换本机追踪。小球每 5 秒换色，轨迹会保存柔光尾巴；算法追踪历史是与其明显不同的反色高对比虚线和空心方形采样点，默认保留 28 秒，可在折叠分析面板中调节为 8~45 秒。**轨迹完全是随机变化的，而不是固定循环。**

若 `xdg-open` 未能打开浏览器，手动访问 `http://127.0.0.1:8765/`。启动脚本占用当前终端，按 **Ctrl+C** 结束本地服务；如果只是体验动画，也可独立双击 `index.html`。

## 2. 开始真正的 YOLO 神经网络识别

预训练通用模型（COCO 里的 `sports ball`）不保证能识别霓虹发光小球，因此提供了**自动标注的合成训练集生成器**和**单类别 YOLO 训练程序**，不假装预训练权重已经适配。

在另一个终端执行（同一项目目录）：

```bash
.venv/bin/python generate_dataset.py --train 720 --val 160
.venv/bin/python train_yolo.py --epochs 35 --batch 8
```

训练完成后权重路径：`runs/ball_yolo/weights/best.pt`。训练脚本默认使用 `yolo11n.pt` 做迁移学习，首次下载权重、安装依赖需要联网；之后可离线推理。模型训练依赖计算资源，CPU 可运行但通常较慢，有 NVIDIA GPU 可使用 `--device 0`。例如：

```bash
.venv/bin/python train_yolo.py --epochs 35 --batch 8 --device 0
./start.sh yolo
```

这会启用**真正的 YOLO 模型检测**，且禁用经典识别兜底；没有 `best.pt` 时会明确报错，而不是伪装 YOLO 成功。使用 `./start.sh` 则保持 YOLO 优先 + 经典检测补充的混合模式。

合成样本的背景、颜色、曲率、尾迹、大小、位置都随机化，YOLO txt 标签只标注实体球体，不包含拖尾。想进一步提高真实屏幕上的准确性，可以补充**真实网页截图并标注球体**，与合成数据一起训练。

## 3. 单独运行屏幕/视频跟踪器（可选）

```bash
# 先在浏览器打开 index.html（最好先按 H 隐藏文字）
.venv/bin/python tracker.py --source screen --mode classical

# 训练出权重后使用 YOLO，输出每帧状态到 CSV
.venv/bin/python tracker.py --source screen --mode yolo --csv results.csv

# 从已有视频中识别
.venv/bin/python tracker.py --source video --video my_recording.mp4 --mode hybrid

# 离线合成场景测试，不要求浏览器、抓屏或者训练权重
.venv/bin/python tracker.py --source demo --mode classical
```

`--region LEFT,TOP,WIDTH,HEIGHT` 可指定屏幕区域，`--monitor 1` 可选择显示器。OpenCV 监视窗口按 `Q` 退出、Space 暂停。一个显示器使用桌面抓屏时，监视窗口若遮挡小球会干扰识别；推荐使用第一种网页 Canvas 回传路径，或者把监视窗口放在另一块显示屏。

Ubuntu Wayland 环境下 MSS 的 X11 抓屏权限可能不可用，**不需要因此改操作系统**，可以使用推荐的 `local_server.py` 画布像素路径。

## 4. 核心算法

**随机曲线运动（网页）**：分段随机机动、相关噪声、加速度限制、平滑速度逼近、边界软转向。随机参数连续变化，碰壁的硬反弹只作为安全兜底。三种轨迹模式对应不同转向尺度与机动频率。每 5 秒改变颜色，视觉上保留长尾。

**检测**：YOLO 负责学习发光球体形状，OpenCV 传统基线使用 HSV 饱和度/亮度、形态学开运算、轮廓圆度和候选抑制。两者都只看渲染像素，不查询 `ball.x` / `ball.y`。YOLO 与经典方法可以进行精度和速度对照实验。

**卡尔曼估计器**：6 维常加速度状态

```
x = [px, py, vx, vy, ax, ay]^T
z = [px, py]^T
```

`F(dt)` 通过离散运动学更新，`Q(dt)` 使用连续白噪声 jerk 模型的严格积分形式；观测更新采用 Joseph 形式协方差更新以维护数值稳定性。卡尔曼预测新位置后用 Mahalanobis 距离做观测门控，短暂漏检会保持估计，超过 3 秒则重新获取目标。未来 350 ms 的位置、预测误差椭圆显示在画面里。**随机运动无法被无误差地预知**：预测区间越远，不确定性越大，急转向时误差会增大，这是正常现象。

**实验评价**：`tracker.py --source demo --csv demo.csv` 输出检测点、滤波状态、未来位置。**网页实验模式采取推理与评估分离**：Python 检测器只接收 Canvas JPEG 像素，不接触小球坐标；网页评估侧保留小球真实球心，并在 Python 返回检测结果以后独立计算误差。检测/状态估计误差对齐到**图像采集时刻**；未来预测误差仅在预测对应的未来时刻真实到达后计算，图表会标注真实运动中的明显变向事件。结果以 px 为单位，RMSE 为接收到的有效状态估计样本累计，变向事件包含局部估计误差峰值与恢复时间。因为浏览器渲染采样、JPEG 编码与推理存在延迟，仍可能有少量对齐误差，这套结果适合调试，不应视为已验证的学术基准。

## 6. 常见问题

- **以前页面有背景但小球消失**：旧版本首帧 `requestAnimationFrame` 时间差有可能是负值，让随机漫游公式中的 `Math.sqrt(dt)` 产生 `NaN`，动画绘制停止。v3 已限制时间差为非负，并在检测到非法坐标时自动恢复。更新后请在浏览器用 `Ctrl+Shift+R` 强制刷新，并确认打开的是 `http://127.0.0.1:8765/?v=4.1`，而不是旧的文件标签页。
- **更新 v3 时不必重新安装**：停止旧终端服务，`cd ~/Downloads && unzip -o chaotic_ball_yolo_kalman_fixed_v3.zip && cd neon_ball_lab && ./start.sh`。保留现有 `.venv`、已训练权重及实验数据。
- **误差图暂时是空白**：小球与变向事件不依赖 Python，但算法误差需要先启用「演示追踪」或「连接本机算法」收到图像检测结果后才有数值。
- **看到“连接失败·重试”**：先确保终端里 `local_server.py` 正在运行，并且 `http://127.0.0.1:8765/health` 返回 `ok: true`。页面永远只连接自己电脑的 `127.0.0.1`。
- **没有 YOLO 权重**：`./start.sh` 启动的本地服务默认以经典视觉算法运行；请先生成数据集并训练，之后再 `./start.sh yolo`。
- **模型慢**：减小 YOLO 的 `--imgsz`（如 640），减少网页分辨率，或使用 NVIDIA GPU；小球在低分辨率下会更难识别。CPU 实时帧率无法保证。
- **球突然大幅度转弯而预测偏离**：这是不可预知机动与固定时长预测的正常矛盾，可以调小 `--future`（例如 `.15`）或尝试 IMM/UKF。
- **安全/隐私**：监听地址仅为本机 `127.0.0.1`。上传像素是网页小球画布画面，不是整个桌面。安装 Ultralytics 和下载预训练权重需要联网。

参考：<https://docs.ultralytics.com/usage/python>、<https://docs.ultralytics.com/models/yolo11>、<https://python-mss.readthedocs.io/latest/usage.html>。

## V4.0：多小球物理碰撞与百分制追踪评分

- 页面左上角 **+ / −**：增加、减少参与碰撞的球（总数 1～8）。初始只有一个球。
- **#1 小球是唯一追踪评估目标**；其余小球属于干扰目标。多球可能导致演示算法或本地 YOLO 发生错误关联，评价时仍只和 #1 的真实坐标比较。V4.0 **不是完整的多目标 MOT ID 追踪器**。
- **制造碰撞**：在主球前方生成迎面运动的干扰球，方便测试预测模型在突发碰撞时是否偏离目标。
- **碰撞恢复系数**：调节 0.35～1.00，采用两球圆形碰撞的法向冲量与位置修正。质量与球半径的平方成正比；干扰球受轻微阻尼并在边界反射；#1 球还会受到主动随机转向控制，因此这是带驱动的简化二维物理模拟，不是完全无外力系统。
- **碰撞计数**：页面左上角实时显示。
- **评分面板**：点击右上方「展开误差分析」，误差面板下方新增「算法综合评估 · 满分100」，以及「重置评估」。
- **一键清尾**、演示追踪、反差色检测框、轨迹预测、变向事件、`+350ms` 预测评估仍保留。

### 评分方法（针对 #1 号目标）

| 分项 | 满分 | 评分依据 |
|---|---:|---|
| 目标检测精度 | 25 | 检测 RMSE + 检出比例 |
| 状态估计精度 | 25 | 估计 RMSE + 有效估计比例 |
| 未来预测精度 | 30 | 到期后 `350ms` 预测 RMSE + 预测覆盖率 |
| 变向 / 碰撞恢复 | 15 | 变向/碰撞后估计误差峰值 + 恢复成功比例 |
| 检测连续性 | 5 | 检出率 |
| **总计** | **100** | 五项分数相加，上限 100 |

误差相关项将 RMSE 用 `exp(-RMSE/尺度)` 映射到 0～1，尺度与 #1 号球半径相关；该映射是本实验自定义评分，不是 YOLO 官方 mAP 或跨数据集可比的标准。**误检、漏检、追踪到其他球会拉低得分**。若未采集至少 20 帧、10 个到期预测样本以及至少一次有估计误差记录的变向/碰撞事件，则展示「采样中」而不会虚构一个分数。

**注意：** 训练时输入给视觉检测器的仍然只有主画布像素；真实球心只在评估模块用于误差对比。初始演示使用前端亮白核心像素连通域识别 + αβ 滤波，**不是已经训练好的 YOLO**。如果你已经训练出 YOLO 权重，运行 `./start.sh yolo` 然后点击「连接本机算法」，可以得到实际本地 YOLO + Kalman 的单目标评估分数。 

新版本仍使用你之前的 `qiu` 快捷启动命令（前提是已按之前方法配置），或在项目目录运行 `./start.sh`。启动后访问：

`http://127.0.0.1:8765/?v=4.1`

变更球数量时，误差累计评分会自动重置，以便比较不同干扰数量；按「重置评估」可以在球数不变的情况下重新采样。此前的一键清尾**不会重置误差数据**。

## V4.1：真正的多目标追踪算法（MOT）基线

新增 `mot_core.py`：CV 卡尔曼（每球一个）、协方差门控 + 带未匹配虚拟列的匈牙利分配；维护暂时丢失轨迹，在潜在碰撞附近提高过程噪声。每个目标输出 `MOT #ID`、估计中心、速度、未来 350ms 预测点及是否暂时失联。**这是独立的算法追踪 ID，不能保证等于真实物理球编号**。

`local_server.py` 的 `/frame` 现在另外返回 `tracks: [...]`，前端在切换「连接本机算法」时显示所有已确认轨迹的独立方框、ID 和长尾。旧的单目标误差与百分制评分继续只评估 #1 真实球，并**不等同于多目标 MOT 评分**。网页默认的无需 Python「演示追踪」仍是单目标演示。

安装新增的 SciPy 依赖（已有 Ultralytics 时通常已安装）：

```bash
cd ~/Downloads/neon_ball_lab
.venv/bin/python -m pip install 'scipy>=1.11,<2'
./start.sh classical     # 经典视觉检测 + MOT
# 或训练权重后： ./start.sh yolo
```

**先跑不需网页、不需 YOLO 的视频测试**：

```bash
.venv/bin/python mot_video.py --source demo --frames 160 --output mot_demo.mp4
xdg-open mot_demo.mp4
```

**运行在现有视频上**：

```bash
.venv/bin/python mot_video.py --source video --video your_clip.mp4 --mode classical --output tracked.mp4 --frames 2000
# 自己训练出多目标 YOLO 权重后：
.venv/bin/python mot_video.py --source video --video your_clip.mp4 --mode yolo --output tracked_yolo.mp4 --frames 2000
```

**生成适合多球（1～8 个）的训练数据**，再训练真正的多球 YOLO：

```bash
.venv/bin/python generate_multi_dataset.py --train 1000 --val 200
.venv/bin/python train_yolo.py --data dataset_multi/data.yaml --epochs 40 --batch 8
./start.sh yolo
```

注意：现有旧版 `generate_dataset.py` 主要是单球数据，**不能视为针对多球遮挡训练充分**。这个新生成器增加多头同图、多条长尾和局部重叠，但仍是合成数据，应补充真实网页采样帧并标注。碰撞和完全遮挡可能让视觉身份不可辨：即使有卡尔曼及匈牙利匹配，也可能发生 ID switch；后续可与 Ultralytics ByteTrack (`model.track(...,persist=True,tracker='bytetrack.yaml')`)、OC-SORT 和 IMM 做公平对比。

推荐后续单独建立多目标评估：DetA/IDF1/HOTA、ID switch、轨迹完整度、各球位置 RMSE、+350ms 预测误差和碰撞后恢复时间。真实坐标只在**评估端**使用，不送入多目标跟踪器。本版不声称已有权重在真实多球视频上达到特定精度，亦未改变 V4.0 既有百分制单目标评分口径。
