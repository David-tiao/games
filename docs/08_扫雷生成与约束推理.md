# 08｜扫雷：自定义雷数、首击安全和约束推理

## 实际模块

`hub/learning/mines.html` 实现棋盘和游戏交互；`assets/mine-config.js` 管理雷数设置与埋雷；`assets/mines-ai.js` 根据**已揭开的数字与标旗假设**做逻辑推断。

## 棋盘与埋雷

默认三种难度：9×9/10雷、16×16/40雷、30×16/99雷；可以自定义各自雷数。保留首击和其周围八格形成的最多 3×3 安全区，因此安全上限按可用候选格计算。首次点击后从允许集合中无重复抽取指定个数的雷，确保**实际数量等于配置数量**。非法输入必须拒绝而不破坏当前局面。

揭开 0 数字后执行队列/BFS 洪泛展开，不能越界；非零数字只揭开相应格子。胜负根据真实雷图与安全格揭示情况判定，但**提示算法不得读取这些隐藏事实**。

## 约束建模

对已经揭示的数字 n，设周边未知格变量 x_i ∈ {0,1}，若已标旗数为 f，则：

\[
\sum_{i\in U}x_i=n-f
\]

其中 U 是未揭示且未标旗的邻格集合。推导规则：
- 右侧为 0 → 剩余格必安全；
- 右侧等于 |U| → 剩余格必为雷；
- 若 U_A ⊂ U_B 且两个方程可相减，则对集合差 U_B\U_A 生成新约束，继续推理。

~~~mermaid
flowchart TD
  VIS[仅输入可见数字/旗帜] --> EQ[建立前沿约束]
  EQ --> ZERO[零剩余雷规则]
  EQ --> ALL[全剩余雷规则]
  EQ --> SUB[集合包含差分]
  ZERO --> SAFE[可证明安全格]
  ALL --> MINE[可证明雷格]
  SUB --> SAFE
  SUB --> MINE
  EQ --> UNKNOWN[仍不能确定时不给假保证]
~~~

## 局限与验证

标旗是玩家提供的假设，错误标旗会影响推断。没有足够信息时只能说明无法确定，**不是完整概率求解器，也不能偷看隐藏地雷**。测试精确雷数、首击安全、零区展开、集合包含逻辑、非法数值和移动端输入体验。12 节课程围绕数字、约束、集合差分和推理练习展开。
