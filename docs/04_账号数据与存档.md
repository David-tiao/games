# 04｜账号、认证、存档与迁移

> **当前 V1.3 的会话令牌七天过期，不等于游戏存档七天自动删除。** 统一账号、统一服务端存档及 168 小时清理仍未实现。

## 当前数据归属

| 数据 | 位置 | 服务重启后 |
|---|---|---|
| 围棋账号 | `apps/go-online/server/data/users.json` | 保留 |
| 五子棋账号 | `apps/gomoku-online/server/data/users.json` | 保留 |
| 登录令牌 | 各自后端内存 Map | 消失，重新登录 |
| 真人房间 | 各自后端内存 Map | 消失 |
| 大厅语言、主题 | 浏览器 localStorage | 同一浏览器通常保留 |
| 扫雷自定义雷数 | 浏览器 localStorage | 同一浏览器通常保留 |
| 星阵关卡记录 | 浏览器本地数据 | 依客户端存储策略 |
| 光轨追踪会话 | Python 进程内存 | 消失，空闲会话另有短期回收 |

## 密码与会话

围棋和五子棋各自注册与登录：校验用户名/密码 → 生成随机盐 → Node.js `scrypt(password, salt, 64)` → 保存密码哈希 → 登录时使用 `timingSafeEqual` 验证。账号数据采用临时文件再 rename 的写入策略。会话令牌采用随机字节生成，保存在服务进程内存，签发后约七天到期；重启服务器要求重新登录，但原账号仍在。

~~~mermaid
flowchart TB
  A[围棋登录] --> GO[scrypt 验证]
  GO --> GOU[(围棋 users.json)]
  GO --> GS[围棋内存会话]
  B[五子棋登录] --> GM[scrypt 验证]
  GM --> GMU[(五子棋 users.json)]
  GM --> MS[五子棋内存会话]
  C[浏览器设置] --> LS[localStorage]
~~~

## 七天存档：尚待实施的独立系统

新存档表建议包含 `user_id`、`game_id`、`schema_version`、`state_json`、`saved_at_utc`、`expires_at_utc`；必须保证：

1. 从最后一次**成功保存**起计算 168 小时；
2. 读取时检查是否过期，后台每小时清理；
3. 登录、查看进度、断线重连不延长到期；
4. 过期删除的是游戏进度，不是账号和密码哈希；
5. 允许导出、恢复和版本化迁移，并验证访问权限。

~~~sql
CREATE TABLE game_saves (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  game_id TEXT NOT NULL,
  schema_version INTEGER NOT NULL,
  state_json TEXT NOT NULL,
  saved_at_utc TEXT NOT NULL,
  expires_at_utc TEXT NOT NULL
);
CREATE INDEX idx_game_saves_expiry ON game_saves(expires_at_utc);
~~~

该 SQL 是**设计提案而不是当前实际数据库**。

## 迁移与备份

启动脚本的 `scripts/migrate-old.sh` 用于检查旧数据迁移，必须先审查来源目录、目的目录及覆盖规则。旧目录清理脚本 `cleanup-old.sh` 与文档上传无关，不应执行。

停止游戏服务器后，将两个 `server/data` 目录备份到非公开位置；其中可能含密码哈希与盐，**禁止加入公开 Git 仓库**。迁移后用既有账号在新大厅重新登录验证。当前两款棋类账号相互独立，统一身份需要设计用户名冲突及 ID 映射策略。
