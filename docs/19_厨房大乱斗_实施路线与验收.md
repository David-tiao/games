# 19｜《厨房大乱斗》实施路线、测试与发布验收

> **V0.1 原创浏览器游戏已开发，V0.2–V1.0 是后续路线。** 已实现本地双人／单人、切菜、汤、装盘、订单、暂停和结算；V1.9 大厅第七款游戏已可直接打开。旧版 C++/raylib MIT 移植仍保留为独立可选构建，不是新 Canvas 游戏的基础代码。联网、AI 厨师与更多地图尚未实现。

| 阶段 | 目标 | 要实现的功能 | 退出门槛 |

## 2. V0.1 已采用的开发顺序

~~~mermaid
flowchart TD
  C[规则常量 / 瓦片地图] --> W[玩家移动与碰撞]
  W --> ITEMS[食材对象唯一归属]
  ITEMS --> STATION[拾取/放下/工作台交互]
  STATION --> RECIPES[菜谱 DAG 与加工]
  RECIPES --> ORDERS[订单队列/过期/得分]
  ORDERS --> UI[Canvas 渲染与输入]
  UI --> TEST[自动化 + 浏览器手工验收]
  TEST --> GATE[3300 网关 / 第七张大厅卡片]
~~~

**集成原则：** 新游戏暂时独立在 `apps/kitchen-chaos/`；只有 V0.1 已能启动并且验证过 HTTP 资源路由，才在 `hub/server.mjs` 和 `hub/public` 新增 `kitchen`。当前已经上线第七个厨房入口；仍保留原有六款游戏、旧账号和启动脚本。

## 3. 单元测试与不变量

### 规则安全

- **物品不复制**：所有物品 id 唯一，同一时刻恰有一种归属（手持/工位/地图）。
- **工位状态合法**：空砧板不能凭空切菜；未经加工的蔬菜不能直接伪装成合格沙拉。
- **时序确定性**：相同种子、相同 tick 输入、相同初态产生一致的状态与得分。
- **碰撞**：厨师不能穿墙、穿过不可通行的灶台或绕过隔墙取物。
- **公平交互**：同一个 tick 两人抢一件物品时必须有确定的唯一结果。
- **暂停安全**：暂停不推进订单时间、烹饪时间和厨房事件。
- **订单状态**：completed/expired 互斥；每个订单只能结算一次。
- **数值安全**：分数不溢出、工作进度不为 NaN、剩余时间不为负。

### 算法正确性

- A* 返回合法路径，且在均匀代价四联通地图中路径步数与 BFS 最短路径一致。
- 配方 DAG 不含环；先后依赖和并行任务时长计算正确。
- AI 不读取未来订单、隐藏结果或客户端无权查看的数据。
- 分工成本解释和真实决策使用同一组参数，不允许展示虚构数字。

## 4. 真实玩家验收场景

| 场景 | 预期结果 |
|---|---|
| 一名玩家完成一单沙拉 | 可完整取菜、切菜、装盘和上菜 |
| 两人合作一单汤 | 可分工切菜/入锅/装盘，无物品复制 |
| 一人拿着盘子再取食材 | 提示持物冲突，不凭空增加一个物品 |
| 订单过期同时送达 | 由固定 tick 的明确处理顺序决定结果 |
| 厨师贴近墙/工位 | 不允许跨越墙或隔台远距离取物 |
| 厨师交换角色或重开 | UI 与引擎状态一致，上一局事件无残留 |
| 手机横屏（如承诺实现） | 按钮可触达，画面不横向溢出 |
| 网络版两人同取菜（V0.3） | 只有一人拿到唯一物品，其他端看到一致状态 |
| 网络版断线与重入（V0.3） | 重新获取权威快照，不重复加分 |

## 5. 量化质量门槛

建议作为验收目标，而不是现在已达到的数据：

- **帧率**：桌面浏览器稳定目标约 60fps；游戏规则固定 20Hz，与渲染速度分离。
- **输入反馈**：本机交互目标小于 100ms；网络版另测 RTT 与状态插值。
- **资源**：可独立运行 V0.1，无强制 Python/YOLO/LLM、无需登录云服务。
- **测试**：厨房新增测试通过，同时根目录 `npm test`、`npm run check` 和现有五款旧游戏回归不退化。
- **安全**：不提交真实用户账号、登录 token、第三方 API Key 和未经许可的商业素材。
- **可恢复性**：游戏未完成前不引入不可逆存档清理；未来保存需明确定义过期语义。
- **可部署性**：`./start.sh` 不破坏既有六款游戏，厨房服务宕机不能带崩整个大厅。

## 6. 联机专项验收（V0.3）

服务端应以固定 tick 执行权威状态，拒绝客户端自报分数、非法食材 ID、过期 seq、同一 tick 物品重复占有。至少测试以下四人场景：

1. 四名真人同时加入同一个房间，同步看到相同订单、厨师位置和灶台进度；
2. 不同客户端同时拾取同一个盘子，最终唯一归属；
3. 烹饪已启动时某人断线，其他人仍能进行；
4. 同一订单只有一次送达奖励，重复提交被拒绝；
5. 网关反向代理 HTTP/WebSocket 都可用，服务端绑定回环地址，重连不泄漏房间外状态。

## 7. 成立与未成立的定义

设计文件落库只意味着**项目规划完成**。完成以下步骤才可以在 README “六款游戏”改成“七款游戏”：

- 实际存在 `apps/kitchen-chaos/index.html`、核心引擎、真实关卡和测试；
- `/play/kitchen/` 可通过 3300 网关打开，而不是静态假卡片；
- 至少单人练习/本地双人完成真实一局；
- 文档准确标明哪些是本机、哪些是网络，哪些是 AI 演示；
- 公开仓库不包含没有权限发布的第三方代码、音乐和素材。

此后才升级项目版本，并通过 GitHub 提交记录说明新增功能与回归情况。
