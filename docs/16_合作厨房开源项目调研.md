# 16｜开源合作厨房游戏调研（2026-11-23）

## 推荐分工：哪份仓库解决哪类问题？

**Delixia**：在开源仓库中实现多人大厅、实时房间、订单倒计时、食材、厨房工位与客户端/服务端同步。适合借鉴多人架构，但项目用 Babylon.js 3D，不应把它描述成现成的 2D Canvas 游戏。Apache 2.0 允许在遵守条款的情况下使用代码；需要保留许可与版权说明，并核对 NOTICE 和第三方素材。

**Overcooked-AI**：开源 MIT 的多智能体合作研究环境，核心是一起收集食材、放入锅中、等待烹煮并端汤。最适合把任务规划、A* 路径、角色分工、动作队列、队友协作和奖励指标做成独立的算法实验室；不等于直接拿到完整原版 Overcooked。

**ChefJeff**：重点是人类与 AI 队友合作，包含中文界面和可扩展实验环境。AGPL-3.0 对网络服务提供修改版本有额外要求，未来真正合并代码前应评估；研究玩法与接口设计不等于复制代码。

**Let's Cook!**：据 README，Next.js + Phaser 3，2 名本地玩家，3 分钟制作沙拉。最接近简单 2D 胡闹厨房的即时玩法，但本次检查仓库根目录没有发现 LICENSE；公开源码并不自动授予复制和分发许可。

## 为《游戏宇宙》推荐的原创 2D 架构

~~~mermaid
flowchart LR
  Browser[Canvas/Phaser 2D] <-->|WebSocket/Socket.IO| Gateway[3300 游戏网关]
  Gateway <-->|HTTP / WS| Rooms[Node.js 厨房房间]
  Rooms --> Orders[订单与配方状态机]
  Rooms --> World[瓦片地图、碰撞与工作站]
  Rooms --> Clock[计时、得分与失败]
  Rooms --> AI[可选 AI 厨师及任务规划]
~~~

优先保持 3300 单入口、浏览器全屏、中英文、独立核心规则与确定性测试。推荐建设阶段：

1. **厨房 V0.1 单机 2 人**：原创 2D 厨师，食材拾取、切菜、烹饪、装盘、上菜、订单及分数。
2. **厨房 V0.2 2–4 人联网**：服务端权威状态、房间、操作序号、断线回归和物品所有权。
3. **厨房 V0.3 算法实验室**：A*、任务 DAG、工位负载、订单调度与 AI 队友的行动解释。
4. **未来十人房间**：只有完成 4 人真实负载验收后才考虑；需要扩大厨房、任务容量、同步与性能预算。

## 版权与许可检查要点

- **Apache-2.0**：保留许可与版权声明，按要求保留 NOTICE，并审核第三方资源许可证。
- **MIT**：保留原版权和许可声明。
- **AGPL-3.0**：可能对向网络用户提供修改版软件产生提供对应源代码的义务，混合发布前需独立合规审查。
- **未找到许可**：不能仅凭仓库公开就认定可自由复制、修改及发布。
- **商用 Overcooked**：不得未经授权复用原作图像、声音、商标和角色；可用原创素材实现独立的合作烹饪玩法。
