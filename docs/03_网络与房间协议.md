# 03｜网络、WebSocket 与多人房间

## 实际拓扑

玩家只访问 `http://主机IP:3300`。Node.js 网关根据 URL 分流到围棋、五子棋的内部 Express/Socket.IO 服务，星阵、扫雷及课程为静态页面；混沌光轨的可选 Python 视觉服务经同域 HTTP 代理访问。

~~~mermaid
sequenceDiagram
  participant B as 浏览器
  participant G as 3300 网关
  participant S as 围棋/五子棋服务
  B->>G: GET /play/go/
  G->>S: HTTP 转发
  S-->>B: 由网关返回页面
  B->>G: WebSocket /play/go/socket.io
  G->>S: Upgrade /socket.io
  B->>G: game:move
  G->>S: 转发操作
  S-->>B: room:state
~~~

## 服务端权威校验

每次落子均检查房间是否存在、登录身份、玩家与房间的绑定、连接是否仍然有效、是否轮到该玩家以及落子是否合法。客户端绘制的棋盘不是胜负的最终权威。

围棋的主要事件包括 `room:create`、`room:join`、`room:rejoin`、`game:move`、`game:pass`、`game:mark-dead`、`game:confirm-score`、`game:resume`、`game:resign`、`game:rematch`、`coach:analyze`、`room:state`。五子棋使用类似的房间与落子事件，但没有围棋数子流程。具体 payload 请核对各游戏的 `server/src/index.js`。

## 房间生命周期

~~~mermaid
stateDiagram-v2
  [*] --> waiting: 创建房间
  waiting --> playing: 对手加入
  playing --> finished: 胜负/认输/和棋
  finished --> playing: 双方同意重赛
  waiting --> [*]: 房主退出
  playing --> scoring: 围棋双方连续 pass
  scoring --> finished: 双方确认分数
  scoring --> playing: 对分数有异议
~~~

- 已断线的玩家可使用相同账号重新加入，旧连接不能继续代替玩家操作。
- 房间使用进程内存；**服务器重启不会恢复旧房间**。
- 围棋和五子棋一局只有两名下棋玩家；**十人同房间协作未实现**。
- 星阵和扫雷的棋盘仍由各浏览器独立维护；混沌光轨 Python 会话按请求会话隔离，但不是十人共享游戏状态。

## 网络与安全验收

局域网两台不同设备验证大厅和五个入口；不同账号测试真人房间创建、加入、交替落子、非法落子、断线重连及重赛。私有地址（10.x/192.168.x）无法直接在公网访问。公网运行前需增加 HTTPS/WSS、代理限流、认证防爆破、请求体大小限制，并对 Python 图像推理端点实施资源保护。
